## OSPF故障排查
- OSPF建立故障排查
	- 卡在down/init状态
		- 接口未使能ospf
			- netowork
		- 接口配置了静默接口配置
			- silent-interface
		- ACL或防火墙过滤了ospf报文
			- 协议号89
			组播地址224.0.0.5/224.0.0.6
		- NBMA网络未手动指定邻居
			- peer
		- 互联端口IP地址掩码不一致
		- 是否采用从地址建立邻居
			- 从地址无法建立邻居关系
	- 卡在2-way/attempt状态
		- MA网络将进行DR/BDR选举（40S），非DR/BDR间不能进入下一状态
		- 所有路由优先级均为0，则不进行DR/BDR选举
			- ospf dr-priority 0
	- 卡在exstart/exchange状态
		- 接口MTU不一致
		- 两端单播IP不可达
		- 互联链路质量差
		- RID冲突
	- 卡在loading状态
		- MTU问题
			- 导致大LSU报文丢弃
			- 即使 DBD 交换完成，携带大量 LSA 的 LSU 也可能因 MTU 不匹配被丢弃
		- 请求的LSA校验错误或不可用
			- 例如 Router ID 冲突导致 LSA 混乱。可用 display ospf error 观察错误增长趋势，结合 display ospf brief 检查全网 Router ID 是否唯一
	- 其他原因
		- 区域ID不一致
		- 区域类型不一致
		- hello/dead时间不一致
		- 认证失败
		- 网络类型不一致
		- 互联IP不在同一网段
		- NBMA/P2MP未指定邻居
		- 接口down，物理层或协议没有UP
		- CPU/内存过高导致设备没有多余资源处理OSPF报文
		- BFD会话DOWN
- OSPF路由无法通告故障排查
	- 无法通告从地址路由
		- 从地址与主地址区域不同
	- ABR无法通告路由
		- 区域不允许接收汇总路由
			- 完全存根/完全NSSA区域的ABR不会向该区域通告其他区域路由
		- ABR与骨干区域隔离
			- 与ABR相连的区域必须有一个骨干区域，如果没有骨干则无法通告区域间路由
		- OSPF骨干区域分割
			- ABR不能通过非骨干区域学习区域间路由
	- 无法通告外部路由
		- 区域不允许接收外部路由
			- 存根/完全存根/NSSA/完全NSSA区域的话外部路由是无法向这些区域通告的
		- NSSA区域多ABR
			- 如果NSSA区域存在多个ABR，具有较大RouterID的ABR才会进行类型7的LSA转换成类型5的LSA操作，其它的ABR不能进行这个转换，如果NSSA区域存在配置错误的ABR而且其RouterID较大，那么该NSSA区域的外部路由可能无法通告到其它区域。
- OSPF路由无法加入路由表故障排查
	- 路由表中没有OSPF路由
		- 网络类型不匹配
		- 点到点网络单边无编号
			- 在OSPF中，表达链路使用借用地址的LSA中所携带的链路数据值与一般链路不同。点到点网络中，如果一端配置有IP地址，另外一边配置为借用IP地址，则二者的LSA链路数据值不匹配，这就导致了OSPF数据库中的不一致，因此不会在OSPF路由表中添加路由。
	- 外部路由无法加入路由表
		- FA（Forwarding Address）地址有效性检查失败
			- OSPF外部路由中会携带转发地址信息，如果该转发地址非零，那么OSPF必须能够通过区域内或区域间路由到达该转发地址，否则该外部路由不会加入OSPF路由表。

## 交换机丢包故障排查（L2 + L3）

- 丢包场景定位
	- 同VLAN内丢包 → 优先排查L2
	- 跨VLAN/跨网段丢包 → 优先排查L3
	- 间歇性丢包 → L2环路/ARP攻击/路由震荡
	- 持续性丢包 → 配置错误/限速/表项满

## L2数据链路层丢包排查
- 端口协商与双工
	- 自协商失败
		- 两端速率不匹配，端口有CRC或runts
	- 双工模式不一致
		- 一端全双工一端半双工 → Late Collision
	- 跨厂商协商兼容性
		- 部分设备间自协商异常需强制设置
- 二层环路
	- STP未开启或配置错误
		- 未启用生成树直接成环 → 广播风暴
	- MSTP/PVST实例与VLAN映射不一致
		- 不同实例阻塞端口不同导致部分VLAN环路
	- 下游环路回流
		- 下游交换机自环导致上游CPU冲高
	- TC报文泛滥
		- 频繁拓扑变更 → 全网MAC表刷新 → 瞬断丢包
- MAC地址表
	- MAC表溢出
		- 表项打满后未知单播泛洪 → 带宽挤占丢包
	- MAC地址漂移
		- 同一MAC在多个端口间跳变 → 转发不稳定
	- MAC老化时间过短
		- 频繁泛洪学习 → 无效流量占用带宽
	- 端口安全/MAC限制
		- 违规MAC被直接丢弃或端口被err-disable
- VLAN与Trunk
	- Access口未加入正确VLAN
		- 终端发出的报文被丢弃
	- Trunk口Allow VLAN列表遗漏
		- 跨交换机VLAN不通
	- Native VLAN两端不一致
		- 未打标签的VLAN在两端映射错误
	- VLAN被误删除
		- 关联接口直接DOWN
	- VLAN数量超出设备上限
		- 新建VLAN无效
- 链路聚合（LACP/Eth-Trunk）
	- 成员口状态不一致
		- HASH不均导致部分流走异常成员口 → 丢包
	- 两端HASH算法不一致
		- 同一条流被分到不同成员口 → 乱序/丢包
	- 成员链路质量不一
		- 某条成员链路存在误码 → 命中该HASH的流丢包
	- 成员口速率不一致
		- 负载分担比例失衡
- 风暴控制与流量抑制
	- 广播/组播/未知单播抑制阈值过低
		- 正常协议报文被丢弃
	- 风暴控制触发后处理动作
		- 端口被err-disable或直接shutdown
- 生成树（STP/RSTP/MSTP）
	- PortFast未在边缘口开启
		- 终端接入后30秒内不通
	- BPDU Guard/BPDU Filter误配置
		- Guard误拦截 → err-disable
		- Filter导致环路不阻断
	- Root Guard/Loop Guard误触发
		- 正常端口被阻塞
- 二层安全
	- 端口安全 → MAC数量超限丢弃
	- VACL（VLAN ACL）误匹配
		- 合法流量被过滤
- 其他L2问题
	- Jumbo Frame支持不一致
		- 一端支持一端不支持 → 大包丢弃
	- Flow Control流控触发
		- 暂停帧导致吞吐量骤降

## L3网络层丢包排查
- ARP相关
	- ARP表项满
		- 新会话无法建立 → 部分IP不通
	- ARP攻击/欺骗
		- 网关MAC被伪造 → 间歇性丢包
	- ARP老化时间过短
		- 频繁ARP泛洪 → CPU冲高
	- 免费ARP风暴
		- 大量设备同时发送 → CPU冲高丢包
	- IP地址冲突
		- 两个设备使用相同IP → 会话中断
- 路由问题
	- 路由表震荡（Flapping）
		- 路由反复添加删除 → 间歇丢包
	- ECMP成员链路质量不一
		- 某条路径误码 → 命中该路径的流丢包
	- 路由黑洞
		- 下一跳不可达 → 匹配路由的流量全部丢弃
	- 路由表溢出
		- FIB装不下 → 部分路由硬件不转发
	- 默认路由指向错误
		- 未知目标流量全部走错路径
	- 策略路由PBR
		- 下一跳不可达 → 匹配流量被丢弃
		- 匹配条件配置错误 → 预期之外的流量被牵引
	- 路由重分发环路
		- 双点双向重分发 → 次优路径/环路
	- BFD检测失败
		- BFD会话DOWN → 路由频繁切换
- VRRP/HSRP网关冗余
	- 主备频繁切换
		- 虚IP对应虚MAC反复迁移 → 会话中断
	- 优先级配置错误
		- 预期Master与实际Master不一致
	- Track链路检测失败
		- 误触发主备切换
- 三层接口
	- MTU不匹配
		- 大包无法通过 → 分片失败或DF置位丢弃
	- 接口IP地址冲突
	- 子接口VLAN终结配置错误
		- VLAN与BD/VPN绑定不一致
- IP分片与MTU
	- 路径MTU超限且DF置位
		- 中间链路MTU小于报文大小 → 丢弃+ICMP不可达
	- 隧道封装增加开销
		- GRE/IPSec/VXLAN封装后超出链路MTU
	- PMTUD被中间设备阻断
		- ICMP不可达被ACL过滤 → 发送端不知情
- 三层ACL
	- ACL误匹配正常流量
		- 规则范围过大
	- 规则顺序错误
		- 前面的规则覆盖了后面的精确匹配
	- TCAM资源不足
		- 部分ACL未下发硬件 → 未生效
	- ACL应用到错误方向/接口
		- 入方向与出方向搞反
- 三层安全
	- uRPF（单播逆向路径转发）误丢弃
		- 非对称路径 → 流量被当成伪造报文丢弃
	- IP Source Guard误拦截
		- DHCP Snooping绑定表不匹配
- 组播（L3 Multicast）
	- PIM邻居关系异常
		- 组播路由无法建立
	- RPF检查失败
		- 组播流量从非预期接口到达 → 丢弃
	- RP（汇聚点）不可达
		- 共享树无法建立
	- IGMP Querier配置错误
		- 组成员关系无法维护

## L2+L3交叉问题
- SVI（VLAN接口）
	- SVI未UP
		- 该VLAN下没有物理口UP
	- SVI IP地址与ARP冲突
	- SVI下ACL/QoS误配置
- 堆叠/虚拟化
	- 堆叠分裂
		- 双主冲突 → 全网丢包
	- 跨框转发带宽不足
		- 堆叠链路拥塞
- 跨层MTU
	- L2开启Jumbo但L3接口MTU未调整
		- 交换机转发没问题但三层终结时丢包
	- 隧道封装未同时考虑L2头+L3头开销

## 排查方法论
- 第1步：明确丢包层
	- 同VLAN丢包 → L2排查路径
	- 跨VLAN丢包 → L3排查路径
	- 间歇性 → 环路/ARP攻击/路由震荡
	- 持续性 → 配置/限速/表项满
- 第2步：L2关键命令
	- display interface
		- 查看 CRC / 错误包 / 双工 / 速率
	- display mac-address
		- 查看 MAC 表、漂移记录
	- display stp brief
		- 查看 STP 状态、根桥、端口角色
	- display stp topology-change
		- 查看 TC 报文变更次数
	- display eth-trunk
		- 查看聚合成员口状态
	- display vlan
		- 查看 VLAN 与端口映射
	- display storm-control
		- 查看风暴控制状态
- 第3步：L3关键命令
	- display arp
		- 查看 ARP 表、是否冲突
	- display ip routing-table
		- 查看路由表是否完整
	- display vrrp brief
		- 查看 VRRP/HSRP 状态
	- display ip interface brief
		- 三层接口状态
	- display acl all
		- ACL 规则及命中计数
	- display fib
		- 硬件转发表是否与路由表一致
- 第4步：分段隔离手段
	- 缩小范围：全网 → VLAN → 端口 → IP
	- 替换法：更换光模块/线缆/端口/设备
	- 对比法：正常VLAN与异常VLAN配置对比
	- 抓包法：端口镜像 + Wireshark/tcpdump
	- 路由追踪：traceroute 逐跳定位丢包节点
